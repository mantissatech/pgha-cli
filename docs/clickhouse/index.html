Section 17

ClickHouse

pgha runs ClickHouse for analytics on its own cluster: 1 shard, 3 replicas, and ClickHouse Keeper on the same 3 nodes. It reuses the network, firewall, SSH key and port, Tailscale, host hardening, the load balancer, the state store, alerts and down.

./pgha clickhouse up --name events                  # 3 nodes in fsn1, nbg1, hel1
./pgha clickhouse up --name events --public-lb      # also a public address, TLS
./pgha clickhouse status --name events              # nodes and endpoints
./pgha clickhouse db create --name events app       # database and user "app"
./pgha clickhouse db list --name events             # passwords and URLs
./pgha clickhouse db drop --name events app --yes   # deletes the data

In the console, choose ClickHouse on New cluster. Open the cluster and choose ClickHouse to make, drop and connect to databases.

#How it works

  • The cluster always has 3 nodes, one in each location (fsn1, nbg1, hel1 by default). Keeper needs 2 of 3 for a quorum, so the cluster survives the loss of one node or one location.
  • The default server is ccx23 (4 dedicated vCPU, 16 GB) with a 100 GB volume at /mnt/data. Data is in /mnt/data/clickhouse.
  • ClickHouse comes from the LTS channel of the ClickHouse apt repository, pinned. Updates of clickhouse-* wait for a planned window.
  • Each database uses the Replicated engine, made ON CLUSTER pgha. Make tables with ReplicatedMergeTree, with no arguments, and they copy to every node.
  • Users and grants live in Keeper, so a user made on one node works on all.
  • db create makes a database and a user with the same name. The user owns the database and nothing else. Its profile pgha_app turns on async_insert (many small inserts become one part), caps one query at 40% of memory, and stops queries after 600 seconds.
  • The admin user pgha and the check user pgha_health sign in from localhost only. The default user is removed.

#Connect

Clients use TLS through the load balancer:

PortProtocolExample
8443HTTPShttps://app:<password>@<lb>:8443/?database=app
9440Native, TLSclickhouse://app:<password>@<lb>:9440/app?secure=true

Trust the CA from pgha ca-cert, or download it in the console. The certificate of each node names the load balancer's private and public addresses. The plain ports 8123 and 9000 stay on the private network.

The load balancer sends clients only to a node that passes a check on port 8011, path /clickhouse. The node passes when Keeper answers, no table is read-only, and no replica is more than 300 seconds behind. A node that lost Keeper becomes read-only, so the check takes it out of the pool. ClickHouse's own /replicas_status does not do this: it answers 200 for a read-only replica.

#Failure behaviour

What failsWhat happens
One node or one locationThe other two serve reads and writes. The node catches up when it is back.
Two nodesKeeper has no quorum. Tables are read-only and the check fails, so the load balancer stops traffic until a second node is back.
All nodes restartClickHouse waits for Keeper. systemd restarts it every 5 seconds until the quorum is back.
A certificate changesup writes the new files. ClickHouse reloads them with no restart.

#ClickHouse backups

./pgha clickhouse up --name events --backup-endpoint fsn1.your-objectstorage.com \
  --backup-bucket events-backups                     # S3 keys: PGHA_S3_ACCESS_KEY, PGHA_S3_SECRET_KEY
./pgha clickhouse backup list --name events          # backups and the backup log
./pgha clickhouse backup run --name events           # a full backup now
./pgha clickhouse backup test --name events          # restore test now
./pgha clickhouse backup restore shop --name events  # newest backup; --from NAME picks one

Backup flags on a later clickhouse up turn backups on for a live cluster. In the console, open the cluster and choose Backups.

  • What: a full BACKUP of every database except system and pgha, each night at 01:30 UTC. The newest --backup-keep-full (default 7) stay; older ones and unfinished ones older than a day are deleted.
  • Where: pgha/<cluster>/clickhouse/backups/<name>/ in the bucket. The name is the start time, for example 20261107T013000Z.
  • Encryption: ClickHouse encrypts each file with AES-256 before it leaves the node. The key is made per cluster and kept in the state store, with the other secrets. Without it, a backup cannot be read. App users cannot back up to, restore from or list the backup disk: that needs READ ON DISK and WRITE ON DISK, which pgha gives no app user.
  • One node: every node runs the timer. The node with the lowest address whose check on port 8011 passes makes the backup: every replica holds all the data. BACKUP … ON CLUSTER is not used, because it waits forever for a node that is down.
  • Restore test: every Sunday, after the backup, one node restores the newest backup into local copies of each table, runs CHECK TABLE, counts rows, and drops the copies. The copies use MergeTree, so they do not replicate and do not touch Keeper. It uses at most half the free disk; larger tables are skipped, and the log says how many.
  • Log: each backup, test and restore writes a row to pgha.backup_log, a replicated table that every node reads. Rows stay 90 days.
  • Alerts: ch_backup fires when the last backup failed or none finished in 26 hours. ch_restore_test fires when the last test failed or none passed in 8 days. Both start counting at setup.
  • Restore: backup restore DATABASE restores one database on every node with RESTORE DATABASE … ON CLUSTER. All 3 nodes must take clients. The database must not exist; --replace drops the live one first, and its data since the backup is lost. The user and its password stay: users are not in the backup, so pgha makes them again.
  • down --delete-backups deletes the cluster's folder. The bucket stays.

#ClickHouse limits

  • One shard. For more data, scale up the server type or the volume.
  • Backups are full each night, not incremental: the bucket holds about keep times the compressed data.
  • A restore needs all 3 nodes, and restores one database at a time.
  • No SQL editor in the console yet.
  • No Postgres change copy (CDC) yet.
  • A ClickHouse cluster has no Postgres, Redis, PgBouncer or --tls mode, and adopt does not set it up.
  • The cluster has exactly 3 nodes.
