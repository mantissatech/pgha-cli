Section 6

Run the console on a server

This guide puts the web console on a small server that is always on. The team uses it from a browser. Nobody needs pgha.db or the SSH key on a laptop.

You need:

  • A Linux server with Docker. A Hetzner cx23 with Ubuntu 24.04 is enough.
  • The Hetzner API token.
  • For existing clusters: their SSH key and pgha.db, or remote state.

Choose how people reach the console:

WayGood forNeeds
A. SSH tunnelOne person, or a few people with SSH access to the serverNothing more
B. HTTPS with CaddyA team in the browser, with Firebase or Supabase sign-inA domain name, ports 80 and 443
C. TailscaleA team that already uses TailscaleTailscale on the server and on each laptop

Do not publish port 7070 on a public address. The console has no TLS.

#6.1 Create the server

With the hcloud CLI, or the same in the Hetzner Console:

hcloud server create --name pgha-console --type cx23 \
  --image ubuntu-24.04 --location fsn1 --ssh-key my-key

hcloud firewall create --name pgha-console
hcloud firewall add-rule pgha-console --direction in --protocol tcp \
  --port 22 --source-ips 203.0.113.7/32          # your address
hcloud firewall apply-to-resource pgha-console \
  --type server --server pgha-console

For way B, also open ports 80 and 443 to all addresses. Caddy needs port 80 to get the certificate:

hcloud firewall add-rule pgha-console --direction in --protocol tcp \
  --port 443 --source-ips 0.0.0.0/0 --source-ips ::/0
hcloud firewall add-rule pgha-console --direction in --protocol tcp \
  --port 80 --source-ips 0.0.0.0/0 --source-ips ::/0

The Hetzner firewall sits outside the server. It also covers ports that Docker opens, which ufw on the server does not.

The console reaches the nodes with SSH on their public address. The cluster firewall (<name>-fw) allows SSH from the --ssh-allow ranges. The default is all addresses. If you set a narrow range, add the public address of the console server to <name>-fw.

#6.2 Install Docker

ssh root@<server-ip>
curl -fsSL https://get.docker.com | sh

#6.3 Folder, key and state

On the server:

mkdir -p /srv/pgha/data/.ssh
cd /srv/pgha

From your laptop, copy the key and the state of existing clusters. Skip this for a fresh start; the image then makes a new key.

scp ~/.ssh/id_ed25519 root@<server-ip>:/srv/pgha/data/.ssh/id_ed25519
scp pgha.db root@<server-ip>:/srv/pgha/data/pgha.db

Then, on the server, give the files to the container user:

chown -R 10001:10001 /srv/pgha/data
chmod 700 /srv/pgha/data /srv/pgha/data/.ssh
chmod 600 /srv/pgha/data/.ssh/id_ed25519 /srv/pgha/data/pgha.db 2>/dev/null || true

For a team that also uses the CLI, use remote state in place of copying pgha.db. Set PGHA_DATABASE_URL in the next step. Read The state file.

Settings go in /srv/pgha/.env. Only root reads it:

cat > /srv/pgha/.env <<EOF
HCLOUD_TOKEN=your-read-write-token
PGHA_CONSOLE_TOKEN=$(openssl rand -hex 32)
EOF
chmod 600 /srv/pgha/.env

Add PGHA_S3_ACCESS_KEY, PGHA_S3_SECRET_KEY, TS_API_KEY or PGHA_ALERT_WEBHOOK here when you use them.

#6.4 Way A: SSH tunnel

/srv/pgha/compose.yaml:

services:
  pgha:
    image: ghcr.io/mantissatech/pgha:latest   # or pin a release, like :1.2
    restart: unless-stopped
    env_file: .env
    ports:
      - "127.0.0.1:7070:7070"
    volumes:
      - ./data:/data
    stop_grace_period: 30m

Start it and read the link:

docker compose up -d
docker compose logs pgha

On your laptop, open a tunnel, then open the link from the log:

ssh -N -L 7070:127.0.0.1:7070 root@<server-ip>
# http://localhost:7070/auth?token=...

The port is open on the server's loopback only. Only people who can SSH to the server can reach the console.

#6.5 Way B: HTTPS with Caddy

Point a DNS record, for example pgha.example.com, to the server's public address. Then use this /srv/pgha/compose.yaml:

services:
  pgha:
    image: ghcr.io/mantissatech/pgha:latest
    restart: unless-stopped
    env_file: .env
    environment:
      PGHA_CONSOLE_ALLOWED_HOSTS: pgha.example.com
    volumes:
      - ./data:/data
    stop_grace_period: 30m

  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
      - "443:443/udp"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy-data:/data
      - caddy-config:/config

volumes:
  caddy-data:
  caddy-config:

/srv/pgha/Caddyfile:

pgha.example.com {
	reverse_proxy pgha:7070
}
  • The pgha service has no ports. Only Caddy reaches it, on the Compose network.
  • Caddy gets a certificate from Let's Encrypt and renews it.
  • Caddy keeps the Host header and sets X-Forwarded-Proto: https. The console then marks its cookie Secure.

Start it with docker compose up -d. With token sign-in, the log shows a link for localhost. Use your domain in its place: https://pgha.example.com/auth?token=....

For a team, sign in with Firebase or Supabase. Add to .env:

PGHA_CONSOLE_AUTH=supabase
PGHA_SUPABASE_URL=https://abc.supabase.co
PGHA_SUPABASE_ANON_KEY=eyJ...
PGHA_CONSOLE_AUTH_ALLOW=@example.com
PGHA_CONSOLE_AUTH_METHODS=password,google

In the provider, allow the console address. For Supabase, add https://pgha.example.com/ to the redirect URLs. For Firebase, add pgha.example.com to the authorized domains. Read Sign-in. Run docker compose up -d again after a change to .env.

#6.6 Way C: Tailscale

Join the server to your tailnet:

curl -fsSL https://tailscale.com/install.sh | sh
tailscale up
tailscale ip -4      # for example 100.101.102.103

/srv/pgha/compose.yaml:

services:
  pgha:
    image: ghcr.io/mantissatech/pgha:latest
    restart: unless-stopped
    network_mode: host
    env_file: .env
    environment:
      PGHA_CONSOLE_LISTEN: 100.101.102.103:7070
      PGHA_CONSOLE_ALLOWED_HOSTS: pgha-console,pgha-console.your-tailnet.ts.net,100.101.102.103
    volumes:
      - ./data:/data
    stop_grace_period: 30m
  • The console listens on the Tailscale address only. Tailscale encrypts the traffic.
  • The host network also lets pgha reach nodes made with --tailscale.
  • If the container starts before Tailscale is up, it fails and Docker starts it again.

Open http://pgha-console:7070/auth?token=... from a laptop in the tailnet. Use your tailnet ACLs to choose who can reach port 7070.

#6.7 Update

cd /srv/pgha
docker compose pull
docker compose up -d

Check the Operations page first. Compose waits up to stop_grace_period for running tasks. A task stopped before its end shows as failed. up is safe to run again.

#6.8 Back up the server

/srv/pgha/data holds the passwords of every cluster and the SSH key. Keep a copy in a safe place:

cd /srv/pgha
docker compose stop pgha
tar -czf pgha-data-$(date +%F).tgz data
docker compose start pgha

With remote state, back up that database instead. The server then holds only the SSH key.

#6.9 Without Docker

Install pgha from the apt or yum repository, then run it with systemd:

useradd --system --create-home --home-dir /var/lib/pgha --shell /usr/sbin/nologin pgha
install -d -o pgha -g pgha -m 700 /var/lib/pgha/.ssh
sudo -u pgha ssh-keygen -t ed25519 -N '' -f /var/lib/pgha/.ssh/id_ed25519
install -d -m 700 /etc/pgha
install -m 600 /dev/null /etc/pgha/console.env
# Then put HCLOUD_TOKEN=... and PGHA_CONSOLE_TOKEN=... in that file

/etc/systemd/system/pgha-console.service:

[Unit]
Description=pgha web console
After=network-online.target
Wants=network-online.target

[Service]
User=pgha
WorkingDirectory=/var/lib/pgha
EnvironmentFile=/etc/pgha/console.env
ExecStart=/usr/bin/pgha console --listen 127.0.0.1:7070
Restart=on-failure
KillMode=mixed
TimeoutStopSec=30min

[Install]
WantedBy=multi-user.target
systemctl daemon-reload
systemctl enable --now pgha-console
journalctl -u pgha-console     # the sign-in link

KillMode=mixed stops pgha first and lets its running SSH tasks end. The state is /var/lib/pgha/pgha.db. Reach the console with way A, B or C as above. For Caddy without Docker, use reverse_proxy 127.0.0.1:7070 and set PGHA_CONSOLE_ALLOWED_HOSTS.

#6.10 Checklist

  • Port 7070 is not open on a public address.
  • .env and data/ are readable by root and uid 10001 only.
  • PGHA_CONSOLE_TOKEN is long and random, or sign-in uses Firebase or Supabase with a short PGHA_CONSOLE_AUTH_ALLOW list.
  • Everyone who can sign in can delete clusters and run SQL as the postgres superuser. Give access with care.
  • SSH to the console server is limited to your addresses.
  • The server gets security updates (unattended-upgrades on Ubuntu).
  • You have a copy of data/ or of the remote state database.
