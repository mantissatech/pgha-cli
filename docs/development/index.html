Section 26

Development

make build      # build the web console, then go build
make web        # build the web console only
make web-dev    # Vite dev server; run pgha console for the API
make site       # build the documentation site into site/build
make site-dev   # documentation site with live reload
make test       # go test ./... and svelte-check
make lint       # go vet ./...
make snapshot   # goreleaser snapshot into ./dist
make image      # container image pgha:dev from the Dockerfile

A tag v* publishes the release. The public repository pgha-cli then builds the container image ghcr.io/mantissatech/pgha-cli from the release binaries. The README section "Releases" lists the token, the public repository, apt, yum, Homebrew, Scoop, and the image.

#Documentation site

This file is the source of https://mantissatech.github.io/pgha-cli/. The SvelteKit app in site/ splits it at each ## heading into one page, and builds static HTML at build time. Each ### heading is in the "On this page" list and in the search.

  • Links such as [Backups](#16-backups) go to the right page. The build fails on a link to a heading that does not exist.
  • The Docs workflow builds the site on each pull request. On main it runs scripts/publish-docs.sh, which copies the site to the gh-pages branch of mantissatech/pgha-cli.
  • That branch also holds the apt and yum repositories. The script changes only the files listed in .pgha-docs-files. It never changes dists/, pool/, yum/, README.md, .nojekyll or the archive key.

Tests that need local services are off by default:

Code rules used in this project:

  • Comments have 7 words or fewer.
  • Function names have 4 words or fewer.
  • User messages have 10 words or fewer.
  • Use context.Context in all calls that do I/O.
  • Check all values before they go into a shell command or SQL text.
