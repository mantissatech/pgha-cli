Section 8

The state file

In local mode, pgha keeps its state in one SQLite file: <state-dir>/pgha.db, or the path in --db or PGHA_DB. The file has mode 0600. All commands and pgha console use the same file. SQLite lets several pgha processes use it at the same time.

The file has two tables:

TableContent
clustersOne row per cluster: the name and the secrets as JSON.
operationsConsole task history: kind, status, times, log, error. The newest 1000 stay.

The secrets JSON has these keys:

KeyContent
superuser_passwordPassword of the cluster superuser.
replication_passwordPassword of the replicator role.
patroni_api_passwordPassword for the Patroni REST API (user patroni).
backup_cipher_passphrasePassphrase that encrypts the backups.
backup_s3_access_key, backup_s3_secret_keyS3 keys, if backups are on.
tailscale_auth_keyTailscale key, if Tailscale is on.
networkName of the existing private network, when --network was used.
pgbouncer_passwordPassword of the pgbouncer role.
databasesPassword of each project database.
connection_limitsConnection limit of each project database.
monitorWebhook URL and alert thresholds, when alerts are on.

monitor holds webhook_url, lag_mb, disk_free_pct, repeat_min, and backup_every_min. The numbers are the saved values, never zero. down leaves this object in the file.

#Old secrets files

Older versions wrote <state-dir>/<name>.pgha.json. When pgha opens the state file, it copies each such file that it does not have yet and prints a note. It never changes or deletes the old file. After you check the copy (pgha state export --name <name>), delete the old file.

#pgha state

CommandMeaning
state pathPrint where the state is.
state listList clusters with saved secrets.
state export --name NPrint the secrets of N as JSON, in the old file format.
state import FILE --name NSave secrets from a JSON file. --force replaces saved secrets.

#Modes

ModeState
local (default)SQLite file on this computer.
remoteReserved for a later state service. It stops with "remote mode is not available yet".

Select the mode with --mode or PGHA_MODE. To move a cluster between computers or modes, use state export and state import.

Rules:

  • Keep the state file safe. Back it up, or keep a state export copy in a password manager.
  • Without the secrets, up refuses to run on a cluster that has servers. New passwords would not agree with the old nodes.
  • Without the backup passphrase, you cannot read the backups.
  • Do not commit the file. The .gitignore excludes pgha.db* and *.pgha.json.
