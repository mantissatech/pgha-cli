Section 10

What runs on each node

Cloud-init runs the script /usr/local/sbin/pgha-bootstrap one time, at the first start. The log is /var/log/pgha-bootstrap.log.

The script does these steps:

  1. Waits for the data volume and mounts it at /mnt/pgdata.
  2. Waits for the private address.
  3. Joins Tailscale, if --tailscale is on.
  4. Adds the PostgreSQL package source (PGDG).
  5. Installs PostgreSQL, Patroni, etcd and the optional tools.
  6. Writes the configuration files.
  7. Starts etcd and Patroni.
  8. Enables pgha-monitor.timer, if --monitor is on.
  9. Creates /var/lib/pgha-bootstrap.done.

/usr/local/sbin/pgha-pooler-initPatroni post_init script (PgBouncer on). It runs once, on the node that creates the cluster, and makes the pgbouncer role and its login lookup function. Mode 0700.
/var/lib/postgresql/tls/ca.crt, server.crt and server.key (TLS on). The key has mode 0600. Postgres and PgBouncer both use them.
/var/log/pgha-bootstrap.logInstall log.

#Services

systemd unitWhen
etcdAlways
patroniAlways. Patroni starts and stops Postgres.
pgbouncerWith --pgbouncer
pgha-backup.timerWith backups
pgha-monitor.timerWith --monitor or pgha monitor install

Do not start or stop Postgres with systemctl or pg_ctl. Use patronictl.

The web console installs nothing on the nodes. Its monitoring and database explorer send short Python scripts over SSH. They run as the postgres user with python3 and python3-psycopg2, print one JSON line, and exit.
