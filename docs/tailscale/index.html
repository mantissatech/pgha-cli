Section 15

Tailscale

export TS_API_KEY=tskey-api-...
./pgha up --tailscale
ssh root@prod-pg1

With --tailscale and TS_API_KEY:

  • pgha lists the tailnet and deletes devices whose hostname is a node name, or that name plus -1, -2, and so on.
  • A device whose hostname is a node already in this cluster is kept. An adopted server's exact hostname is kept.
  • pgha creates a reusable, pre-authorized auth key that expires in one day. The nodes join with it.
  • The API token is stored in the state file. It is not written to the nodes.
  • The firewall has no public SSH rule.
  • The backup, db, and monitor install commands and the web console reach the nodes over the tailnet. Your computer must be on it.

How pgha finds a node on the tailnet: it reads tailscale status --json on your computer and uses the Tailscale IPv4 address of the online device with the node's hostname. When more than one online device has that hostname, the one whose MagicDNS name is exactly the node name wins. Without the tailscale command, or with the daemon stopped, pgha uses the node name and relies on MagicDNS.

At boot, a node checks its own MagicDNS name. If Tailscale named it <name>-1 because an old device owns the name, the node tries to take the name back for about 10 seconds. If it cannot, it logs out and the bootstrap stops with Tailscale name <name> is already used.

TS_AUTHKEY remains a fallback when no API token is set. The auth key must be reusable. That fallback cannot delete a device that already owns the name. If the name is taken, the node logs out and stops instead of registering as name-1.

If the join fails, a node has no SSH path. Use the Hetzner web console to get access, then read /var/log/pgha-bootstrap.log.

down deletes the tailnet devices through the API before it deletes the servers. Without a saved API token, it logs each reachable node out over SSH. An adopted cluster is left on the tailnet.
