Section 15

PgBouncer and connection limits

./pgha up --pgbouncer
./pgha db create shop_api --connections 10

#What changes with --pgbouncer

  • Each node runs PgBouncer on port 6432, in front of its local Postgres.
  • The load balancer sends ports 5432 and 5433 to port 6432 on the nodes.
  • Connection strings do not change.

#PgBouncer settings

SettingValue
pool_modetransaction
default_pool_size--pool-size (default 20)
max_client_conn2000
max_prepared_statements200
auth_typescram-sha-256

#Login check

PgBouncer does not keep a user list. It connects to the postgres database as the role pgbouncer and calls the function public.pgha_user_lookup. Cluster setup creates this role and function. db create creates them again if they are missing. The function does not return superusers or replication roles, so these roles cannot log in through PgBouncer.

#Connection limits

--connections N sets two things:

WhereWhatEffect
PostgresALTER ROLE ... CONNECTION LIMIT NHard limit.
PgBouncerpool_size=N for the databaseExtra queries wait.

Without PgBouncer, a client above the limit gets the error too many connections for role.

The tool writes the limits to /etc/pgbouncer/pgha-databases.ini on each node and reloads PgBouncer. If a node was not reachable, run pgha db sync.

Keep the total of all pool sizes below about 180. Postgres allows 200 connections, and Patroni and replication use some.

#What does not work in transaction mode

  • SET for the session (use SET LOCAL in a transaction).
  • LISTEN and NOTIFY listeners.
  • Session advisory locks.
  • Temporary tables that you keep across transactions.

Prepared statements work. The Go pgx driver works in its default mode.
