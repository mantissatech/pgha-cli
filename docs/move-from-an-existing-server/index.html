Section 17

Move from an existing server

There are two paths. Path 1 is safer.

Path 1: importPath 2: adopt
Old serverNot changedBecomes node one
DowntimeTime of the copy (if you stop writes)One Postgres restart
RiskLowHigher
ResultThree equal new nodesOne old node, two new nodes
Best forSmall and medium databasesDatabases too large to copy

#17.1 Path 1: build new, then copy

./pgha up
./pgha db import shop_api \
  --from 'postgresql://user:password@old-server:5432/shop'

What db import does:

  1. Creates the database and login, the same as db create.
  2. Checks that the target database is empty. If not, it stops.
  3. Runs pg_dump on the leader node against the old server.
  4. Sends the dump to pg_restore. The project login owns all objects.
  5. Prints the number of tables.

Rules:

  • The leader node must reach the old server on its Postgres port.
  • The pg_dump version on the node must be the same as or later than the old server version.
  • Writes to the old database during the copy are not included. Stop the application first.
  • Only "trusted" extensions are created automatically (for example pgcrypto, citext, uuid-ossp). For others, install the package on all nodes and create the extension as a superuser first.
  • Use PGHA_SOURCE_URL to keep the password out of your shell history.

#17.2 Path 2: adopt the server in place

./pgha adopt --server my-old-db

Requirements:

  • A Hetzner Cloud server. Dedicated (Robot) servers are not supported.
  • Ubuntu or Debian Postgres packages (the pg_lsclusters layout).
  • Exactly one online Postgres cluster, on port 5432, version 13 to 18.
  • The server is a primary, not a replica.
  • SSH access as root on its public IPv4 address.
  • New-node volumes larger than 1.3 times the data size.

What adopt does:

StepWhereAction
1Old serverRead-only check. The tool prints the plan and the bill.
2HetznerCreates the network, firewall, load balancer and two new nodes. --network uses that network instead of creating one.
3HetznerAttaches the old server. The default address is 10.0.1.11. An existing attachment is kept.
4New nodesInstall software and start etcd. Patroni stays off.
5Old serverInstalls Patroni and etcd. Joins etcd.
6Old serverCreates the roles pgha_admin and replicator.
7Old serverAdds access rules at the top of pg_hba.conf.
8Old serverStores the live settings as the cluster settings.
9Old serverStarts Patroni. It attaches to the running Postgres.
10Old serverRestarts Postgres one time. This is the downtime.
11New nodesStart Patroni. They copy the data and become replicas.

Safety:

  • Steps 1 to 8 do not stop Postgres.
  • If step 9 or 10 fails, the script puts back postgresql.conf, pg_hba.conf and start.conf, and starts Postgres under the old service.
  • The script keeps copies with the ending .pgha-backup.
  • The script does not change the password of the postgres role.
  • You can run adopt again. It completes the missing parts.

What you must know:

  • Applications must move to the load balancer address. A direct connection to the old server stops to work after a failover.
  • The old server keeps its data on its current disk.
  • The new firewall is not applied to the old server.
  • These settings are copied to the cluster settings: max_connections, worker and lock limits, shared_preload_libraries, work_mem, maintenance_work_mem, random_page_cost, effective_io_concurrency, WAL size limits, time zone and date style. Other custom settings stay on the old server only.
  • New nodes need the same extension packages: --extra-packages postgresql-16-postgis-3.
  • Password rules in pg_hba.conf on the new nodes use md5. This method accepts both MD5 and SCRAM passwords.
  • adopt does not set up backups or PgBouncer.
  • down is blocked.

To leave the cluster by hand, on the old server:

systemctl disable --now patroni
cd /etc/postgresql/<version>/main
cp -p postgresql.conf.pgha-backup postgresql.conf
rm -f postgresql.base.conf
cp -p start.conf.pgha-backup start.conf
systemctl restart postgresql@<version>-main

Then delete the new nodes, load balancer and network in the Hetzner console.
