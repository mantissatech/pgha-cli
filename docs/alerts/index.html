Section 16

Alerts

Each node can run a check once a minute and post one JSON webhook per condition. The timer stays off until you ask for it. Your computer does not need to stay on.

export PGHA_ALERT_WEBHOOK=https://example.test/hook
./pgha up --monitor

On a cluster that already exists:

export PGHA_ALERT_WEBHOOK=https://example.test/hook
./pgha monitor install

adopt --monitor installs the timer on the new nodes and on the existing server.

up does not change a node that already exists. If --monitor is set and any node already existed, up still succeeds and prints:

monitor installs on new nodes; run pgha monitor install

Run pgha monitor install to put the same files on those nodes.

#Flags

up, adopt, and monitor install accept these flags. estimate does not. --monitor is only on up and adopt.

FlagDefaultMeaning
--monitoroffInstall the timer on nodes created in this run.
--lag-mb100Alert when replica lag is above this many MB (1 to 100000).
--disk-free-pct10Alert when free space is below this percent (1 to 50).
--repeat-min30Minutes between repeat alerts (1 to 1440).
--backup-every-min15Minutes between backup checks (1 to 1440).

A flag you type replaces the stored value. A flag you leave out keeps the stored value. The first save stores the default for each flag you leave out.

The webhook comes only from PGHA_ALERT_WEBHOOK. It must be https and it must have a host. A path and a query are allowed. http is refused. The tool reads the variable only when --monitor is set, or when monitor install runs. monitor install reuses the saved URL when the variable is empty.

#Checks

The timer is pgha-monitor.timer. It starts about one minute after boot, then every minute, with up to 15 seconds of delay. The script is /usr/local/sbin/pgha-monitor.

CheckWho sendsWhen it fires
diskEach nodeFree space on the filesystem of the Patroni data directory is under --disk-free-pct. New nodes use /mnt/pgdata. An adopted server uses its existing data directory.
lagA node that is not the leaderReplica lag is above --lag-mb, or the lag value is missing.
poolEach node, when PgBouncer is installedcl_waiting is above zero.
patroniEach nodeLocal Patroni is down, or patronictl list fails.
backupThe leader, when backups are onpgbackrest check fails. The check runs at most once per --backup-every-min.
primaryOne nodeThere is no healthy primary.
member:<name>The leaderThat member is missing or not healthy.

Most checks need two bad runs in a row before the first alert. The backup check alerts on the first failure. A later healthy run sends resolved. While a condition stays bad, the alert repeats after --repeat-min minutes.

One node sends the primary, backup, and member alerts. Each node sends its own disk, lag, pool, and patroni alerts. If etcd is down, each live node may send its own patroni alert.

A check that does not apply logs nothing. Every check that ran writes one journal line: pgha-monitor <check> ok, pending, firing, or resolved.

#Webhook body

{
  "cluster": "pgha",
  "node": "pgha-pg2",
  "check": "disk",
  "status": "firing",
  "summary": "8% free on /mnt/pgdata",
  "since": "2026-10-05T12:00:00Z"
}

node is the node that sent the alert. status is firing or resolved. A resolved alert uses the summary recovered. since is the UTC time of the first bad run. check is disk, lag, pool, patroni, backup, primary, or member:<name>.

Other summaries include lag 240 MB, no primary, pgha-pg3 missing, data directory missing, and pgbouncer unreachable.

A failed POST is logged as pgha-monitor webhook failed and retried on the next run. The timer still exits 0.

#Stop and update

There is no disable command. On a node:

systemctl disable --now pgha-monitor.timer

pgha monitor install enables the timer again and is how you change the webhook or the thresholds later. down deletes the servers. The webhook stays in the state file.

monitor install tries every node that has an SSH host. If one node fails, the others still receive the files. The command then prints one line per failed node: install failed on <name>. Run it again. It does not delete open alerts.

Cloud-init user data must stay at or under 32 KiB. A node with backups, PgBouncer, Tailscale, and the monitor still fits under that limit.
