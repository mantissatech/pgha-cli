Section 5

Container image

Each release also ships a free, public container image with the CLI and the web console. No login is needed to pull it.

docker pull ghcr.io/mantissatech/pgha-cli:latest
TagMeaning
latestThe newest stable release.
1.2.3One release.
1.2The newest patch release of 1.2.

A prerelease such as 1.3.0-rc.1 gets only its own tag. The image runs on linux/amd64 and linux/arm64.

What is in the image:

  • pgha, the OpenSSH client and CA certificates, on Alpine Linux.
  • It runs as the user pgha (uid 10001), not as root.
  • /data is a volume. It holds the state file /data/pgha.db and the SSH key in /data/.ssh. It is also the home directory of pgha.
  • The default command is console. It listens on port 7070.

#Run the web console

export HCLOUD_TOKEN=your-read-write-token
docker run -d --name pgha \
  -p 127.0.0.1:7070:7070 \
  -v pgha-data:/data \
  -e HCLOUD_TOKEN \
  -e PGHA_CONSOLE_TOKEN="$(openssl rand -hex 32)" \
  --restart unless-stopped \
  --stop-timeout 1800 \
  ghcr.io/mantissatech/pgha-cli:latest

docker logs pgha    # prints the sign-in link
  • -p 127.0.0.1:7070:7070 opens the port on your computer only. Open the link from docker logs in a browser.
  • With PGHA_CONSOLE_TOKEN the link stays the same after a restart. Without it, each start makes a new token.
  • The console answers only the names localhost and 127.0.0.1. To use another name, set PGHA_CONSOLE_ALLOWED_HOSTS. Read Run the console on a server.
  • docker stop asks the console to stop. It waits for running tasks. --stop-timeout 1800 gives them 30 minutes before Docker kills them.

Flags go after the image name, and the variables in Environment variables work with -e:

docker run -d -p 127.0.0.1:7070:7070 -v pgha-data:/data -e HCLOUD_TOKEN \
  ghcr.io/mantissatech/pgha-cli:latest console --session-ttl 8h

#Run CLI commands

Every command works in the container. Give the command after the image name:

alias pgha='docker run --rm -it -v pgha-data:/data -e HCLOUD_TOKEN -e PGHA_S3_ACCESS_KEY -e PGHA_S3_SECRET_KEY -e TS_API_KEY ghcr.io/mantissatech/pgha-cli:latest'

pgha estimate
pgha up --name prod --pgbouncer
pgha status --name prod
pgha db create shop_api --name prod
  • -it lets up and down ask before they change anything. In scripts, leave out -it and pass --yes.
  • -e NAME without a value copies the variable from your shell, when it is set.
  • Use the same volume (pgha-data) for the console and the commands. They then share the state file and the SSH key.
  • A command that reads a file, such as state import, needs the file in the container. Mount it: -v "$PWD/backup.json:/in/backup.json:ro".

#The SSH key

pgha uses SSH to reach the nodes. At each start the image looks for a key in this order:

  1. /data/.ssh/id_ed25519, when it exists.
  2. PGHA_SSH_PRIVATE_KEY (the key text), or PGHA_SSH_PRIVATE_KEY_FILE (a file path in the container). The key is saved as /data/.ssh/id_ed25519.
  3. Otherwise it makes a new ed25519 key and prints a note.

It writes id_ed25519.pub next to the key. New clusters get that public key. The key must not have a passphrase; there is no SSH agent in the container.

Show the public key:

docker run --rm -v pgha-data:/data --entrypoint cat \
  ghcr.io/mantissatech/pgha-cli:latest /data/.ssh/id_ed25519.pub

Clusters made before, with your own key, need that key. Copy it into the volume once. This replaces a key that the image made:

docker run --rm -i -v pgha-data:/data --entrypoint sh \
  ghcr.io/mantissatech/pgha-cli:latest \
  -c 'umask 077; mkdir -p ~/.ssh; cat > ~/.ssh/id_ed25519; rm -f ~/.ssh/id_ed25519.pub' \
  < ~/.ssh/id_ed25519

Or add the new public key to /root/.ssh/authorized_keys on each node.

#The state file

The state is /data/pgha.db in the volume. To bring an existing pgha.db, stop the console, then copy it in:

docker run --rm -i -v pgha-data:/data --entrypoint sh \
  ghcr.io/mantissatech/pgha-cli:latest -c 'umask 077; cat > /data/pgha.db' \
  < pgha.db

Remote state works too: -e PGHA_DATABASE_URL. For Firestore, mount the service account key and set GOOGLE_APPLICATION_CREDENTIALS to its path in the container. The file must be readable by uid 10001. Read The state file.

#A host folder in place of a volume

A folder on the host works, when uid 10001 owns it:

sudo mkdir -p /srv/pgha/data
sudo chown 10001:10001 /srv/pgha/data
docker run -d -p 127.0.0.1:7070:7070 -v /srv/pgha/data:/data -e HCLOUD_TOKEN \
  ghcr.io/mantissatech/pgha-cli:latest

When the image cannot write to /data, it stops and prints the chown command.

#Clusters with Tailscale

With --tailscale, the nodes have no public SSH. pgha reaches them on the tailnet. Run the container on a computer that is in the tailnet, with the host network:

docker run -d --network host -v pgha-data:/data -e HCLOUD_TOKEN \
  -e PGHA_CONSOLE_LISTEN=127.0.0.1:7070 \
  ghcr.io/mantissatech/pgha-cli:latest

With --network host, -p does nothing. Set PGHA_CONSOLE_LISTEN, or the console listens on all addresses of the host.

#Image settings

VariableValue in the imageMeaning

PGHA_DB/data/pgha.dbThe state file.

#Build the image

docker build -t pgha .      # or: make image
docker run --rm pgha --version

The Dockerfile builds the web console and pgha, then copies them into a small Alpine image. Build arguments VERSION, COMMIT and DATE set the --version text. A multi-platform build cross-compiles; only the last stage needs emulation:

docker buildx build --platform linux/amd64,linux/arm64 -t pgha .
