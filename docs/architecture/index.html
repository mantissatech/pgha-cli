#How a client finds the leader

  1. The load balancer calls GET /primary on port 8008 of each node.
  2. Patroni answers 200 only on the leader.
  3. The load balancer sends port 5432 traffic only to the node that answers 200.
  4. For port 5433 the load balancer calls GET /replica. Only healthy replicas answer 200.

The check runs each 5 seconds, with a 3-second timeout and 2 retries.

#How failover works

  1. Each Patroni holds or watches a leader key in etcd. The key expires after 30 seconds (ttl).
  2. If the leader stops, its key expires.
  3. A replica takes the key and promotes its Postgres to leader.
  4. The load balancer health check finds the new leader.
  5. Clients must connect again. Open connections to the old leader are lost.

etcd needs 2 of 3 members to work. The cluster continues when one node is down. It does not continue when two nodes are down.

With --monitor, each node also runs pgha-monitor.timer. Read section 16.
