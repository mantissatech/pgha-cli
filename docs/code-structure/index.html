Section 23

Code structure

The code uses ports and adapters. The core has no Hetzner or SSH code.

main.go
cmd/                         CLI commands (Cobra)
  root.go                    flags, wiring
  estimate.go up.go adopt.go status.go down.go
  db.go backup.go monitor.go print.go
  console.go                 web console server
  store.go                   mode select, opens the state
  state.go                   state path, list, export, import
internal/
  core/
    domain/                  Spec, Bill, Cluster, Secrets, monitor settings
    ports/                   Cloud, Remote, SecretStore interfaces
    services/                use cases
      cluster.go             estimate, up, status, down
      estimate.go            bill calculation
      database.go            db create, list, drop, sync
      import.go              db import
      backup.go              backup run, list, check
      adopt.go               adopt plan and run
      monitor.go             monitor install
  adapters/inbound/
    httpapi/                 web console API, jobs, auth
  adapters/outbound/
    hetzner/                 Cloud port: Hetzner API
    sshexec/                 Remote port: local ssh client
    sqlite/                  Store port: SQLite state file (local mode)
  bootstrap/                 node files
    cloudinit.go             cloud-init for new nodes
    adopt.go                 scripts for adoption
    monitor.go               alert script, units, and install command
    templates/               Patroni, etcd, pgBackRest, PgBouncer, monitor, shell
web/                         SvelteKit console, built into build/
  embed.go                   go:embed of the build
docs/DOCUMENTATION.md        this file

#Add a remote mode

The remote mode is planned. The code has room for it:

  1. Write an adapter, for example internal/adapters/outbound/remote, that implements ports.Store over HTTPS.
  2. Add it to the modeRemote case in cmd/store.go, with its flags (for example the service URL and a token).
  3. All store calls take a context.Context, so the adapter can set time limits and stop requests.

The core services and the console do not change. state export and state import move clusters from local to remote mode.

#Add another cloud

  1. Write a new adapter that implements ports.Cloud.
  2. Select it in cmd/root.go (newService).

The node files in internal/bootstrap have two Hetzner details: the volume device path (/dev/disk/by-id/scsi-0HC_Volume_<id>) and the automatic private network interface.
